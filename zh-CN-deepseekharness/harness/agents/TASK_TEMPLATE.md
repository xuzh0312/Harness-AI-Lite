# 子任务交接模板

本文件供主 agent 填写后作为 `subagent` 工具的 prompt 发送，不作为自动配置。删去说明文字并填入实际路径及配置；输入不足时不要发起有依赖的实现。子 agent 使用新上下文，看不到主会话聊天记录，因此本模板必须自包含。

```text
任务编号：<主任务 ID / 子任务 ID>
角色：<architect / implementer / infra / reviewer>
子 agent 名称：<1–32 个字符，仅小写字母、数字、连字符，须以字母开头，不得为 lead，同一创建者下唯一；如 reviewer-spec-plan-0001>
审查实例与维度：<reviewer-spec／规格符合性，或 reviewer-quality／实现质量；其他角色注明不适用>
审查组与轮次：<任务项或整体审查标识、轮次及同组另一实例；非审查任务注明不适用>
目标与非目标：<具体说明>
Harness 绝对路径：<路径>
Project 绝对路径：<路径；不使用时说明>
Test 绝对路径：<路径；不使用时说明>
子 agent 工作目录（cwd）：<实际绝对路径；与主会话 cwd 可不同>
必读材料：<Harness AGENTS.md、agents/MODELS.md、角色共享协议、角色说明、目标目录规则、需求与计划、相关技能名或 SKILL.md 绝对路径>
功能任务批准组合：<规格书路径与版本、计划路径与版本、相关验收编号；非功能任务注明不适用>
执行阶段与简报：<初次实现／返工／逐项审查／整体审查；原计划中本项简报定位>
输入与基线：<代码提交及已有工作树改动，或受审文件范围；数据版本>
允许读取／修改范围：<具体路径；只读时明确>
已有改动与其他执行者：<需保留内容、冲突边界>
前置依赖：<已满足的输入或尚未满足的条件>
验收标准：<可观察结果>
验证方式与证据位置：<命令、工作目录或人工检查方式>
reviewer 输入与输出：<两实例共用的受审版本、完整任务差异及前置基线、要求来源、执行报告和证据；本实例独立返回所负责维度结论>
权限边界：<是否有明确的提交、推送、profile／插件变更等授权；未授权不执行；子 agent 权限在创建时固定，不能提升>
配置来源：<Harness agents/MODELS.md 实际绝对路径>
创建参数：provider=<...>；model=<...>；reasoning_effort=<...>；创建时显式传入，不依赖继承
配置复核：<list_subagent_models 的查询结果或核对说明>

使用 subagent 新上下文执行本任务；不使用 subagent_fork，不继承主会话聊天记录。
遵守共享协议，按统一格式返回；不更新主任务状态，不嵌套创建 agent。
会写入原始日志、缓存或临时产物时，仅使用授权的 test 位置或系统临时目录，并在报告中说明。
最终回复必须以如下配置行结尾，包括受阻或失败回复。
若 DSH 报告实际路由或取值与创建参数不同，记录报告值；若违反禁用路由规则，停止并报告。
provider／model：<实际 provider/model>；推理深度：<实际 reasoning_effort>
```

主 agent 发送前必须重读 MODELS.md，用对应角色实际值替换配置占位符，保证提示最后一行就是配置页脚。子 agent 名称一经使用不能在同一创建者下复用，同一实现项的两个 reviewer 使用不同且可追溯的名称。
