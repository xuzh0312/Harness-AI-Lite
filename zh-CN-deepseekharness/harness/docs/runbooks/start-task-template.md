# 跨目录任务启动模板

若部署后的三个区域都在同一个父目录下，将该父目录作为 DSH 工作区打开。填写下列内容，并在新会话中交给主 agent 显式读取入口，不依赖跨根目录自动发现。路径跨盘时，分别核对实际访问权限。提示或路径表中的路径不授予写入权限。

```text
按以下 Harness 协议执行任务：

Harness 绝对路径：<实际位置>
Project 绝对路径：<实际位置；不用则说明>
代码目录：<project/code 的实际位置；不用则说明>
Test 绝对路径：<实际位置；不用则说明>

先阅读 Harness 中的 AGENTS.md、agents/MODELS.md、agents/README.md 和 docs/runbooks/main-agent.md，
再阅读目标目录适用的规则，确认实际访问权限和当前改动。
以 Harness 为管理依据，按角色选择工作目录。

任务：<目标、范围、约束及验收要求>
已有任务记录：<绝对路径；新任务则说明>
需阅读的需求或设计：<已有规格书、选定草案或无；需要设计时读取 harness/.agents/skills/UIUX-design/README.md>
允许修改：<范围>
已有验证与数据：<版本、结果、证据或无>
额外交付授权：<只按此处的明确授权执行，例如是否允许提交或发布>

由主 agent 按既定流程选定角色并最终验收。
每次创建子 agent 前，主 agent 读取 Harness 中的 agents/MODELS.md，
使用不设子 agent 路由或推理深度默认值的本地 DSH Spawn，省略 provider、model 和 reasoning_effort，以继承主 agent 的设置。遵守禁用及记录规则；存在冲突覆盖时报告，不另选模型。
若缺少创建能力或无法完成强制独立审查，明确报告阻塞，不静默替代。
```

移动任何区域后，更新[路径表](../paths.md)及运行器的工作区或权限设置。后续会话须重新提供入口，或采用已验证的运行器集成方式；本模板不保证自动全局生效。
