## 工作区域

- harness：项目介绍、规则、需求、计划、决策、技能和角色说明。
- project/code：软件本体的源码、运行所需资源及必要的项目描述、依赖清单和构建配置。
- project/installpark：用户明确要求打包后生成的最终安装包。
- test：所有非软件本体的代码、测试数据、原始日志、缓存、临时输出和验证材料。

实际位置见 [路径表](docs/paths.md)。三个区域可跨磁盘，不假定相邻目录。DSH 会话只有一个工作目录，写入还受会话 workspace 与文件沙盒限制；跨区域工作时由分派明确子 agent 的 cwd，需要写入 workspace 之外的区域时先取得用户批准的权限配置，不绕过沙盒。

“项目代码”仅指实现交付软件本体功能的代码，包括编译后进入软件或运行时被软件使用的实现。源文件不必原样进入安装包。必要的资源、项目描述、依赖清单与构建配置属于配套文件，不因此将测试或工具代码划为软件本体。

测试代码、测试夹具、模拟服务、验证脚本、临时实验代码、构建打包辅助脚本和其他开发工具代码均放 test，不放 project/code 或 harness。harness 仅存放介绍、规则、角色与技能说明、计划、决策、错误知识库和简要日志文档等管理资料，不放可执行辅助代码、原始运行日志或产物。

test 中材料按需组织，不预建固定技术栈；执行命令明确外部测试或工具路径，并记录与软件版本的对应关系。缓存、构建中间产物、非安装包的构建输出、截图录像和测试结果均配置到 test。工具存在无法重定向的固定目录要求时，先报告冲突，由用户明确决定，不静默放宽边界。

只有用户明确要求生成安装包，或明确批准的计划中包含打包任务时，才执行打包并写入 project/installpark。实现完成、测试通过、普通构建或选择交付形式不自动触发打包；打包也不自动授权发布。

## Git 与执行

harness 和 project/code 分别使用独立 Git 仓库，安装包和 test 数据独立保存。跨仓库通过任务编号与版本关联；未经任务授权不初始化、迁移或删除仓库。

主 agent 负责分派与最终验收，四角色职责见 [角色协议](agents/README.md)。角色文档、AGENTS.md 与技能由主 agent 加载和使用；它们不是 DSH 的原生 agent preset。需要强制约束时，可另行申请创建 DSH preset 或扩展包，但不得默认修改 profile。需要 CI 等工具固定目录时，核对是否与上述存放边界冲突；存在冲突先报告，不自行创建例外。

## DSH 运行环境

- **指令加载**：DSH 自动加载用户全局链（`$DSH_HOME/AGENTS.md`、`~/.agents/AGENTS.md`，若存在）与项目链（项目根到当前工作目录）。项目根是最近的 `.git` 祖先，没有 `.git` 时取当前工作目录。以 harness 为工作目录启动会话时，harness/AGENTS.md 属于项目链并自动生效；从其他目录启动时，需显式读取本入口；会话随后触达 harness 文件时，DSH 也会按需注入该文件。
- **技能发现**：本地技能根按优先级为 `<项目根>/.dsh/skills`、`<项目根>/.agents/skills`、自定义目录、`~/.dsh/skills`、`~/.agents/skills`；只识别 `<root>/<name>/SKILL.md` 或 `<root>/<name>.md`，不递归扫描。技能查找以会话工作目录为准：项目根是最近的 `.git` 祖先，没有 `.git` 时取当前目录。因此只有当 DSH 按会话工作目录计算出的项目根是 harness（最近的 `.git` 祖先是 harness；没有 `.git` 时会话工作目录就是 harness）时，harness 的 `.agents/skills` 才会被扫描。若 harness 自身没有 `.git` 且位于更大的 Git 仓库内，项目根是外层仓库，此时直接读取 `SKILL.md` 的绝对路径，或把技能放到外层项目根的 `.agents/skills`。独立 Git 仓库是项目约定，不是 DSH 的发现前提。
- **子 agent**：由 `subagent` 工具创建，可指定 name、cwd、provider/model/reasoning_effort；新上下文不继承聊天记录。`subagent_fork` 继承已完成对话，只用于续接，不用于独立审查。DSH 默认 `maxDepth=1`、`maxActiveSubagents=8`；子 agent 的权限范围在创建时固定，不能从内部提升。
- **原生能力**：goal、schedule、team task、plan mode 是可选便利能力，不替代本规范的规格书、计划、批准组合与验收记录；定时任务只在用户明确要求时创建。
- **变更边界**：安装或启用插件/扩展包、修改 profile 或 agent preset 会影响该 profile 的所有会话，必须由用户明确要求并确认影响；只读调查、验收通过和任务授权都不自动构成这些变更的授权。
