# 跨目录任务启动模板

新会话将以下内容填好后提供给主 agent。它是显式加载入口，不是自动发现配置；目录加入工作区不等于获得写入权限。三个路径可跨磁盘，无需共同父目录。

```text
请按以下 Harness 协议执行本任务：

Harness 绝对路径：<实际位置>
Project 绝对路径：<实际位置；不用则说明>
代码目录：<project/code 实际位置；不用则说明>
Test 绝对路径：<实际位置；不用则说明>

先读取 Harness 中的 AGENTS.md、agents/MODELS.md、agents/README.md、docs/runbooks/main-agent.md，
再读取目标目录适用规则，并确认实际访问权限和当前改动。
将 Harness 作为管理依据，按角色选择工作目录。

任务：<目标、范围、约束与验收要求>
已有任务记录：<绝对路径；新任务则注明>
必读需求或设计：<路径或无>
允许修改：<范围>
已有验证与数据：<版本、结果、证据或无>
额外交付授权：<仅按本次明确说明执行；例如是否授权提交或发布>

由主 agent 按固定流程选择角色并最终验收。
子 agent 每次创建前读取 Harness 的 agents/MODELS.md，
显式使用其中对应角色的模型与推理设置，遵守禁用策略和实际配置记录规则。
创建能力或强制独立审查不可用时，明确报告阻塞，不静默替代。
```

移动任一区域后更新 [路径登记](../paths.md)与运行器的工作区或权限设置。后续会话必须重新提供入口或使用已验证的运行器接入方式；本模板不保证全局自动生效。
