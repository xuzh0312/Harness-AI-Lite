# UIUX-design · 项目体验与界面设计

这是 Harness 显式读取的设计入口。先看任务处在哪一步，再从下表打开与当前决定有关的一篇。已有项目沿用用户认可的设计；单个页面、组件或评审请求直接从问题所在处开始。

## 和用户一起设计

1. **规划时走任务。** 与 [feature-plan](../feature-plan/SKILL.md) 共用一次访谈。用一句话写清谁在什么情境下要做什么、怎样才算完成；走一遍主路径，再走一遍最容易失败的步骤。把发现的功能缺口交用户取舍，由主 agent 写入同一份规格和验收场景。纯后台任务可跳过。
2. **批准后看首稿。** 有界面设计委托时，[UIdesign](../../../agents/UIdesign/AGENT.md) 用实际内容和典型窗口做一张可查看的代表页面。说明一个来自产品本身的设计决定，问用户想保留或调整哪里，等实际答复再展开。用户想比较或首稿仍有分歧时，用同一内容、状态和视口并排展示不同构图或操作方式。
3. **沿选定方向交接。** 默认交付关键页面稿及开发说明，写明入口、主要操作、布局与关键状态、失败恢复和验证结果。拖动、撤销等体验靠静态稿判断不清时再做最小可交互原型。只有线框或未实测时标明范围。新增行为或验收变化交主 agent 按规划规则修订确认。
4. **区分设计与实施。** 独立设计委托按其范围交付；规划批准与实际开发授权按 Harness 流程处理。项目稿件、原型和走查证据依[路径表](../../../docs/paths.md)放在 test，主 agent 在已有记录中引用选定稿及相关验收编号。

## 遇到问题时再读

| 当前要决定什么 | 专项资料 |
| --- | --- |
| 用户真正想完成什么，入口怎么组织，如何观察他能否完成 | [任务、导航与走查](references/tasks-navigation.md) |
| 页面怎样体现这个产品，如何借鉴素材后形成原创方向 | [创意方向与素材](references/creative-direction.md) |
| 信息怎样分主次，中文、数字、配色和窄屏怎么处理 | [排版、色彩与布局](references/visual-hierarchy.md) |
| 表单何时提示，空状态写什么，错误后如何恢复焦点 | [文案、状态与无障碍](references/copy-and-states.md) |
| 操作要不要动，手势怎样跟手、中断和降动效 | [交互与动效](references/interaction-motion.md) |

[素材目录](assets/index.md)供观察。提取它解决问题的原理，用本项目的内容重新设计。不要照搬整页、组件组合、成套配色或动画。
