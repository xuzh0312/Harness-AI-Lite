## 工作区域

- harness：项目介绍、规则、需求、计划、决策、角色和技能说明。UIUX-design 的可复用资料与精选素材随技能分发。
- project/code：软件本体的源码、运行所需资源及必要的项目描述、依赖清单和构建配置，以及作为交付软件运行入口的文件（如项目要求的启动 .exe）。
- project/installpark：用户明确要求打包后生成的最终安装包。
- test：所有非软件本体的代码、测试数据、原始日志、缓存、临时输出和验证材料。项目设计稿、交互原型、走查截图与普通构建产生的可执行文件均在此区。

实际位置见 [路径表](docs/paths.md)。三个区域可跨磁盘，不假定相邻目录。

“项目代码”仅指实现交付软件本体功能的代码，包括编译后进入软件或运行时被软件使用的实现。源文件不必原样进入安装包。必要的资源、项目描述、依赖清单与构建配置属于配套文件，不因此将测试或工具代码划为软件本体。

test 中材料按需组织，不预建固定技术栈；执行命令明确外部测试或工具路径，并记录与软件版本的对应关系。缓存、构建中间产物、非安装包的构建输出、截图录像和测试结果均配置到 test。工具存在无法重定向的固定目录要求时，先报告冲突，由用户明确决定，不静默放宽边界。

只有用户明确要求生成安装包，或明确批准的计划中包含打包任务时，才执行打包并写入 project/installpark。project/installpark 只存最终 ZIP。解压核对和中间文件放 test；核对包的格式与内容，复用同版本已有效的功能验证证据。实现完成、测试通过、普通构建或选择交付形式不自动触发打包；打包也不自动授权发布。

## Git 与执行

harness 和 project/code 分别使用独立 Git 仓库，安装包和 test 数据独立保存。跨仓库通过任务编号与版本关联；未经任务授权不初始化、迁移或删除仓库。

主 agent 负责分派与最终验收，子 agent 职责见 [角色协议](agents/README.md)。工作目录按任务选择，规则加载和目录权限分别确认。角色文档由主 agent 显式读取使用，不是原生运行器配置。需要 CI 等工具固定目录时，核对是否与上述存放边界冲突；存在冲突先报告，不自行创建例外。
