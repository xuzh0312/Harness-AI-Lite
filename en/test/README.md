# Development and test materials

Store all code outside the software implementation and all development materials: test code and data, reproduction and verification scripts, mock services, build and packaging helper scripts, temporary experiments, raw logs, screenshots and recordings, caches, intermediate artifacts, and output other than installers. Organize these according to actual project needs; do not prepare a technology stack in advance.

When running tests, specify the actual paths of the software code and this directory, and link them to the code version. Brief task and bug records belong in harness; final installers go to project/installpark only after packaging is explicitly requested. Report conflicts first if a tool cannot comply with the directory requirements.
