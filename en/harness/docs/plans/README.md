# Execution plans

active stores plans awaiting confirmation and plans in progress; completed stores archived plans that are completed or cancelled. Use the template for complex tasks and a short plan for simple changes.

New features and feature enhancements must first invoke [feature-plan](../../.agents/skills/feature-plan/SKILL.md). The main agent conducts interviews in rounds while maintaining the specification in specs, automatically assigns a shared ID in the form PLAN-0001, and then generates a detailed feature checklist. The specification and plan each have a version and are presented together for confirmation; partial answers do not approve the whole combination. Plans awaiting confirmation also reside in active; after confirmation, track execution in the same file, then move it to completed upon completion. Mark cancelled plans as cancelled before archiving; cancellation does not mean implementation is complete. Keep specifications in specs and update bidirectional references when archiving.

Number plans independently within each project. Revisions and resumed work retain the original plan; increment the versions of substantively changed documents and reconfirm the combination. Implementation checklist items use stable IDs in the form PLAN-0001.01 and reference specification acceptance IDs. Approval evidence, per-item briefs, report summaries, reviews, and resume entries are maintained centrally in the original plan; do not create duplicate progress records.
