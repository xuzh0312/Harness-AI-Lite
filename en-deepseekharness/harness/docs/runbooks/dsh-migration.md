# Codex → DeepSeek Harness migration checklist

Target environment: DSH Desktop `0.2.2-rc.5`. This is a project workflow template, not an application or build task. Deploy the `harness`, `project`, and `test` directories from the DSH edition; this template does not change global DSH settings or install plugins.

| Original issue or deployment risk | DSH adaptation |
| --- | --- |
| Startup instructions pointed to Codex or to directories not shipped in the package. | Use the [startup template](start-task-template.md) to explicitly read [AGENTS.md](../../AGENTS.md). |
| The old dispatch example used `fork_turns=none`, which is not available in DSH; a fixed GPT route could fail when that route is not configured. | Use local `subagent` as shown in the [DSH dispatch procedure](main-agent.md#3-dispatch-and-integration). Omit `provider`, `model`, and `reasoning_effort`, follow the [inheritance policy](../../agents/MODELS.md), and respect the existing model prohibition. |
| Resuming a child, retrieving its report, and recording its settings lacked DSH instructions. | Record the child's name and use `list_agents` and `send_message`. If it cannot be resumed or the main agent's model or effort has changed, create a fresh independent instance and hand off verified context. Record inheritance and the actual values exposed by the runtime; `inactive` does not mean approval. |
| Project procedures in `.agents/skills` may not appear in the DSH session's skill list. | Use `read` for the [project procedure index](../../.agents/skills/README.md) and its entries instead of relying on registration or discovery. Native skills still load through `skill`. |
| A design subagent asking the user directly could stall unattended dispatch. | [UIdesign](../../agents/UIdesign/AGENT.md) returns questions to the main agent, which asks in the main conversation and relays the answers. |
| An external work path may be readable but not writable, and the target Spawn tool does not accept `cwd`. | Prefer a common workspace parent when practical. Check actual permissions for all three areas as described in the [main agent handbook](main-agent.md#1-entry-confirmation-and-task-record) and include the absolute working directory in the handoff prompt. Set `workdir` on the shell tool for commands; it does not change sandbox permissions. Request permission only for the exact operation when needed, or report the blocker. |
| Planning referred to `AskUserQuestion`, which the target DSH setup does not provide. | Use `ask_user_question` in the main conversation for feature and stack planning when available, otherwise ask in chat. Skipping or an empty response is not approval. |
| Host intake is not project approval, and document approval alone does not prove authorization to implement on resumption. | Retain paired specification and plan approval. Record implementation authorization, scope, and evidence separately in the [plan template](../plans/TEMPLATE.md). Both independent reviews must provide a full conclusion before acceptance. |

At deployment, fill in the actual [path table](../paths.md) and confirm that local Spawn has no child route or effort overrides. Recheck when changing the DSH profile. If inheritance cannot be honored, report the blocker rather than silently choosing another model. The template does not validate the deployed project's build, tests, or cross-disk write access.
