# Interface reference materials

## UI Technique Atlas

State the design problem before consulting examples. If a UI is needed but not yet designed, follow the [skill entry](../README.md): ask the user about motion intensity and wait for their answer before shortlisting directions. Read only relevant material; the examples are not the default style.

| Material | What to compare | How to adapt it |
| --- | --- | --- |
| [Layout atlas](<UI技法图鉴/布局图鉴.html>) · [Layout taxonomy](<UI技法图鉴/页面布局设计全景分类参考.md>) | Page structure, navigation placement, information hierarchy, and narrow versus wide containers. | Compare layouts using real project content and decide how it reflows at each size. |
| [Motion and material atlas](<UI技法图鉴/动效与材质图鉴.html>) · [Motion and style taxonomy](<UI技法图鉴/动效界面设计风格全景分类参考.md>) | State feedback, transitions, spatial relationships, and visual materials. | Borrow only what explains the state or action. Check interruption, legibility, and reduced-motion feedback. |
| [Workbench example](<UI技法图鉴/工作台样板.html>) | How queues, filters, detail views, empty states, and error states work together. | Validate the flow with the project's actual tasks and data rather than copying the sample copy or palette. |

Open the HTML in a browser when useful. Otherwise find the item in the taxonomy and read its demo source by ID. Cite the category as well as the number (e.g. Layout 3.4). Approximate or illustrative demos are not evidence of native implementation or testing on the target. At handoff, record the reference, what was adopted, and what changed for the project. See the [atlas usage notes](<UI技法图鉴/图鉴使用说明.md>).
