## Protocol Source and Upgrades

When adopting the template or adding it to an existing project, record the actual template source, runner, language, and a verifiable protocol baseline. Record a version only for a formal release. Otherwise, record the source commit, or the checksum of the original template package if a commit cannot be determined. If the baseline cannot be verified, state that explicitly. Do not label working-tree changes as a release.

Before upgrading, back up the existing Harness and project materials. Use the old baseline to compare the upstream protocol and local changes, then merge only authorized protocol changes. Do not overwrite the user's project overview, architecture, paths, customized rules, plans, decisions, or historical materials with the clean template. Do not move code or verification materials. Resolve conflicts and verify that existing materials were preserved before updating the recorded protocol baseline.
