# Numbering, execution records, and archiving

- **PLAN** is for an initial release or a new feature. When saving the first artifact is authorized, one task planner takes exclusive write ownership of the [hot path](../paths.md) index for this operation. In the same turn, reread the hot table and check for duplicate scope, reuse an existing ID for the same feature, reserve an ID only for a new feature, create the first artifact and register its actual entry point, then release write ownership. Do not split duplicate checks and registration between concurrent sessions. Ask the user if feature identity is unclear. If reservation is interrupted or the hot table is not writable, check who owns the existing directory and who may still be writing before proceeding. Do not reserve a second ID to bypass the problem. Take the largest PLAN number in directories and same-ID proposal filenames under `docs/specs/`, and in filenames under `plans/active/` and `plans/completed/`, then add one (start at 0001). Check names only, without reading cold records. In serial order, create an unused `docs/specs/<ID>/` directory to reserve the ID. If the directory exists, reread and retry without overwriting. Cancelled IDs stay reserved. Reuse the ID of an existing specification or Plan when taking over, reworking, or adding documentation.
- Create artifacts in their [defined steps](../specs/README.md). Create `active/<ID>.md` in step 5. The specification and Plan share the ID and have separate versions. Checklist items such as `PLAN-0001.01` reference proposal AC IDs. Keep subsequent approvals, dispatch, reviews, and progress in the original Plan. For read-only work, use in-chat labels without reserving official IDs.
- **TASK** is only for independent work outside a feature Plan, such as fixing a defect under an existing contract, when it needs review, rework, or a cross-session handoff. In `active/TASK-0001.md`, record the user request and authorization, baseline, changes, the two reviews where applicable, evidence, status, and next step. Once writing is authorized, create `docs/plans/task-ids/` in the same Harness copy as needed. Find the largest TASK number in `task-ids/`, `active/`, and `completed/`, including older records without reservation files, and add one (start at 0001). Permanently reserve the ID through atomic exclusive creation of `task-ids/TASK-<number>.id` (for example, `FileMode.CreateNew`). If it exists, select a new number. Only the successful creator may create the same-ID active file; never overwrite an older record. Retain and back up reservations with task records. Do not move, delete, or reuse reservations after archiving, cancellation, or interruption. Gaps are allowed. Do not assign official IDs without write access to reservations or reliable exclusive creation. Before switching numbering rules, verify that all prior writers have stopped. Cancelled numbers stay reserved. Do not use TASK to bypass a Plan for a feature. Routine Q&A needs no record.
- On completion or cancellation, move the existing Plan or TASK to `completed` under the same name. Update the proposal status and links in both directions. Keep specifications and stage artifacts in place. If cancellation occurs before the Plan exists, update existing stage artifacts only. Confirm relevant instances have stopped writing before closing a cancellation. Update the indexes according to the [hot and cold path rules](../paths.md). Baselines and evidence that active features still use must stay hot.
